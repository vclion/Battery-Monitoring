# 结构与数据流

```text
src/
  Program.cs          命令行入口与单实例控制
  Core/               设备模型、左右选择、配置、进程通信及查询编排
  Devices/            迈从协议、Windows 系统电量、来源路由
  Interop/            HID、SetupAPI、BLE GATT 原生接口
  UI/                 WinForms 托盘、菜单、全黑图标
scripts/              构建、安装、打包
tests/                合成数据测试与测试入口
  integration/        实际托盘消息循环检查
  artifacts/          忽略提交的输出、截图和诊断
docs/                 兼容范围、架构、需求和验证记录
.github/              Windows CI 与设备反馈模板
dist/                 忽略提交的 EXE、ICO 与发布 ZIP
```

点击查询 → 分来源发现设备 → 逐设备读取 → 生成一次快照 → 根据左右选择绘制。
没有定时器查询，启动、设备拔插和唤醒都不主动读取电量。

## 故障隔离

每个发现来源和每个设备使用单独的 `--discover` / `--read-device` 子进程，最多执行 6 秒。主进程异步等待；一个设备卡住后终止该子进程，继续处理后续设备，已经取得的结果仍保留。
一次最多查询 32 个设备，来源发现和设备读取顺序执行，总时长随设备数增长。退出时停止活动读取，不继续发起新查询。

厂商 HID 仅允许精确匹配的 VID/PID 与用途集合；BLE 标准服务通过 Windows 枚举，读取前再次确认设备身份。没有通用的厂商命令探测或固件操作。

## 数据与配置

工作进程协议使用版本标记和 Base64 文本字段，校验来源、类别、设备 ID、电量范围和时间戳。设备路径只用于本地读取进程，不在公开 `--list` 输出或配置中显示。
`%LOCALAPPDATA%\BatteryMonitor\selection.txt` 仅保存左右设备的来源与地址哈希；启动时只读，用户选择时才写入。
正常运行不写电量历史或诊断日志，不联网。Windows 自己维护的设备缓存独立于本项目。

`--read` 保留为原迈从双设备读取的内部兼容入口；日常诊断用 `--list`。内部命令不作为外部稳定 API。
