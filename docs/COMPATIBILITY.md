# 设备兼容范围

兼容性取决于具体型号、连接方式、固件和驱动。识别到设备不等于能够读取电量。

| 读取方式 | 覆盖条件 | 本项目验证状态 |
| --- | --- | --- |
| 迈从 L7 PRO 专用 HID | 2.4G，`5253:1020`，`FF01/0001`，feature report ≥ 21 字节 | 已实机读到电量；本轮鼠标休眠时正确返回未知 |
| 迈从 V9 PRO 专用 HID | 2.4G，`291D:385D`，`FF90/0001`，64 字节 input/output | 本轮实机读到 90%，也观察到读取超时并正确清空结果 |
| Windows 系统电量 | 设备通过 Windows 设备属性公开有效百分比；不限品牌或外设类型 | 属性解析、缓存标注及无设备路径已测试；新增具体型号待实测 |
| 蓝牙驱动电量属性回退 | 蓝牙驱动提供兼容的电量属性 | 已实现，属性并非公开稳定的跨设备契约；具体型号待实测 |
| 标准 BLE Battery Service | Windows 已配对并公开可读的 `0x180F` 服务和 `0x2A19` 特征 | ABI、UUID、数据与异常路径已自动检查；没有 BLE 真机验收 |

Windows 通道可能覆盖蓝牙鼠标、键盘、耳机、手柄等，前提是对应驱动公开电量。BLE 通道不依赖品牌白名单，但设备必须提供标准服务；传统蓝牙音频设备不一定提供 BLE 服务。

## 读数含义

- Windows 读数标为“系统报告”，托盘简写为“系统”。这是操作系统提供的缓存值；查询时间不等于设备更新电量的时间，连接状态也可能未知。
- 系统明确报告未连接时不显示缓存百分比；连接状态未知时保留“系统报告”标记，不声称在线。
- BLE 读取请求使用 `BLUETOOTH_GATT_FLAG_FORCE_READ_FROM_DEVICE`，失败时不自动拿系统缓存冒充这次 BLE 成功读数。设备可能需要保持唤醒。
- 一个物理设备可能有 Windows 和 BLE 两个来源，列表保留来源供选择；同名设备不按名称合并。自动选择优先保留原迈从耳机/鼠标位置，其余设备可以手动指定。
- 设备选择按来源和设备地址生成本地哈希保存。换接口、重新配对或驱动重装后，地址可能变化，需要重新选择。
- 未知、休眠、断开、超时与无效数据使用 `--`，不会显示为 0%；查询失败不会保留此前成功电量。

## 当前不保证的范围

其他型号的私有 2.4G 接收器协议尚未适配，包括不能通过 Windows 属性公开电量的罗技、雷蛇等设备。迈从其他型号也不会仅凭品牌名称套用现有命令。
多电池 BLE 设备目前取首个可读取的标准电量特征，不提供左右耳或电池盒分别显示；不推算充电状态或剩余时长。

新型号反馈方式见 [贡献指南](../CONTRIBUTING.md)。
