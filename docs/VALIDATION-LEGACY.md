## 自动检查

`build.ps1 -Test` 使用本机已有的 .NET Framework 编译器，不访问包源。当前手动查询版 48 项检查通过。检查覆盖：

- 耳机和鼠标电量帧、字段位置、连接和充电状态。
- 真实 0% 与未知、休眠、断开状态的区别。
- 错误命令回显、错误厂商身份、空帧、截断帧、异常电量值。
- 手动模式保留上次查询的读数、异常未来时间戳，以及左右黑色填充存在、中央间隔和外角透明。
- 真实子进程标准输出的 UTF-8 编解码、连续查询、畸形输出、6 秒超时和退出时阻止启动新查询。
- 全黑电量图标以及 16/20/24/32/40/48/64 像素 ICO 加载。2026-11-17 按最新要求改为黑色边框及填充、边框内留白和左右留缝后，48 项检查再次通过；检查了满电、低电、0% 和未知状态的实际 16 像素及放大预览。颜色不再随电量或主题变化。

测试数字为协议测试夹具；正式托盘只使用设备查询结果。

## 托盘运行

- 正式 EXE 已在实际 Windows 会话中启动，系统托盘可识别到耳机 90%、鼠标 57% 的悬停文本。
- 重复启动的进程退出，保留单个常驻实例。
- `tests/artifacts/actual-tray-icon.png` 是此前双环版本的历史截图，当前实心球见 `tests/artifacts/icon-preview.png`。本次仅修改绘制及图标资源，手动查询交互沿用上一版已通过的冒烟验证。
- `ui-smoke.ps1` 在真实 WinForms 消息循环中验证：注册通知图标、查询/启动/退出三项菜单、启动不查询、点击查询读取真实设备、等待 31 秒仍保持同一查询快照、再次点击查询更新、执行实际“退出”菜单处理并移除通知图标。首次查询耳机 90%、鼠标 57%；再次查询耳机 90%，鼠标处于空数据状态，正确显示灰色虚线半环。
- 为避免 UI Automation 在目标进程退出时阻塞，自动冒烟检查直接执行真实菜单项的 `PerformClick`；不声称完成了所有物理鼠标操作的端到端自动化。
- 常驻主进程实测约 32 MB 工作集；一次约 33 秒观察累计 CPU 时间约 0.06 秒。该数值不包含每轮短时查询子进程，不是长期性能基准。
- 按用户要求安装到 `%LOCALAPPDATA%\BatteryMonitor`、创建桌面“电量监控”快捷方式并启用当前用户开机启动。安装检查核对本地 EXE 与构建文件哈希、快捷方式目标、Run 项和运行进程；实际下次登录启动仍待验证。
- 鼠标空闲后实测接收器返回命令回显正确、身份数据全零的报告。此情况显示灰环及“鼠标休眠或未响应”，不继续展示此前的 57%。不能仅凭该报告认定设备已断开。

托盘冒烟输出位于 `tests/artifacts/ui-smoke.txt`，图标预览位于 `tests/artifacts/icon-preview.png`。
